Arc Design System

Building a scalable design system at Upstox: one unified, AI-ready system for app, web, and marketing.

Role
Design System Designer
Timeline
4 Months
Team
Kevin, Siddharth, Chris
Skills
Design Systems, Tokens & Components, Governance
Context

Multi-platform. Multi-product. Growing teams.

Three surfaces

Mobile apps, web apps, and a marketing site, each drifting into its own visual language.

Two systems, one gap

Separate design systems for mobile and web. Nothing at all for marketing.

15 to 20 designers

Design output scaled fast. The shared source of truth did not scale with it.

The Breaking Point

By early 2025, the design ecosystem reached a breaking point.

Inconsistency

The same UI element existed in several forms at once, and no two surfaces agreed.

Rework

Components were overridden instead of reused, so every screen started over.

Developer pain

The same components were rebuilt again and again, from raw values, not tokens.

Core Problems

Five problems.

01
Inconsistency

No variables. Random colors. Duplicate UI across every surface.

02
No scalability

Components overloaded with variants, and nothing built for future brands.

03
High developer effort

Raw values instead of tokens, and every screen reviewed by hand.

04
Override culture

Complex components were overridden instead of reused, so the system drifted.

05
No governance

No quality bar for new components, no ownership, no education.

Constraints

Built under real pressure.

We had to prove value fast, or risk losing momentum entirely.

Time

We built the system while shipping the new Upstox homepage.

Stakeholder buy-in

It generated no revenue, so every hour of it needed justification.

Tool limitations

Figma supported only four modes, which made multi-brand work tricky.

Technical

Heavy reliance on Lottie made motion expensive at runtime.

The Journey

Audit. Brainstorm. Failures. Learnings.

01
Audit

Every screen screenshotted, every component dumped, all motion reviewed.

02
Brainstorm

Monolithic, headless, or one library per platform. We rejected both extremes.

03
Failures

Naming broke MCP. Too many files broke sync. Good components went unused.

04
Learnings

Kebab-case everything. Consolidate by purpose. Teach continuously.

“Balance flexibility for designers with control for the system.”

The guiding principle

The System

Layered variables. Layered components.

Variables

L0
Primitives

Colors, font weights, sizes, radii.

L1
System

Background, text, icon, padding and gaps. Light and dark, compact and relaxed.

L2
Component

Button padding, card elevation, tab icon size.

Components

Base

Foundations, like a base button.

Items and elements

Atomic parts, like a tab item or a dropdown item.

Compositions

Full components built from the two layers above, then code connected by developers and checked in VQA (visual QA) before they ship.

One structure unified app and web, enabled viewport scaling, and made global updates instant.

Motion & AI

Tokens a machine can read.

Standardizing every variable to kebab-case (lowercase-words-separated-by-dashes) was the single decision that unlocked reliable AI parsing.

Motion tokens

Easing, opacity, scale, and timing, standardized and annotated so MCP can read them. The motion designer stopped recreating interactions.

AI in the workflow

MCP lets developers pull design context straight into code. It also lets designers connect Claude to test new variable structures and generate AI-ready components. Prototyping happens directly in Figma Make.

Scalability

Relink, don't rebuild.

New brands, new themes, and new platforms are additions to the system, not rewrites of it.

Variables

A funnel structure. A new surface is added by relinking collections.

Components

Slots hold the uncertain parts, so AI-generated content lands without restructuring the system.

Documentation

Separate guides for feature designers, developers, and new contributors.

Impact

Time saved. Trust built.

The goal was to shorten the path from product conception to release.

55%
Average developer build time reduced, after the layered L0-L2 variable structure shipped
25+
Designers using the component library daily, across web and app
What changed

PMs prototype directly in Figma Make. Developers generate code through MCP and Code Connect. Overrides, rework, and manual QA all dropped, and developers stopped rebuilding what already existed.

Learnings

What worked, what didn't.

What worked

  • Documentation people could actually find.
  • Recorded walkthroughs in a Slack channel.
  • One-to-one sessions with individual designers.
  • Files consolidated by purpose, not by team.
  • Clear ownership for every component group.

What didn't

  • Group workshops on their own.
  • Treating adoption as a launch moment.
  • Parts of the system that grew too complex for daily use.

“Design systems are products, not libraries. A design system should adapt to its users, not force its users to adapt to it.”
