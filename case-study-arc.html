Arc Design System

Upstox's design system had 800+ colour tokens and designers spending more time fighting it than using it. We rebuilt Arc around one idea: designers don't need tokens, they need decisions.

Overview

One design system behind the whole Upstox ecosystem.

Arc powers trading, investing, mutual funds, IPO, insurance, loans and wealth. It began in 2024 as Figma files called “design-system-v2” and by late 2025 had outgrown them. This is a pod's work: where I say “we”, I mean the team.

Simplify

Collapse 800+ tokens and a three-layer model into one semantic layer designers actually reason about.

Consolidate

Pull ~32 scattered components into four cross-platform libraries teams can find and reuse.

Automate

Wire Figma straight into code so tokens and icons can't drift, with syncs designers trigger themselves.

Problem

Designing on Arc had started to feel like debugging.

The system had three problems tangled together, and each one made the others worse.

  • Token overload. 800+ colour tokens, roughly 250 just for backgrounds. Designers spent more time choosing tokens than designing, and still paired them wrong.
  • Fragmentation. Per-component libraries that weren't discoverable, so designers copied old screens instead of using them. Nested instances lagged people's laptops.
  • Drift. With no shared decision layer, every designer applied their own taste, and Home, Holdings and Portfolio started to look like different products.
Opportunity

A hard-to-use system quietly breaks the product.

A design system that's hard to use doesn't just slow designers down. It fails accessibility, blocks releases, and turns the people who own it into a bottleneck.

01
Accessibility broke silently

Wrong token pairings failed contrast, so a system that was hard to use quietly shipped inaccessible screens.

02
Releases got blocked

Broken and undiscoverable components stalled releases while teams hunted for the right part.

03
The pod became the bottleneck

Every team leaned on the DS pod for answers, which turned the people who owned the system into its constraint.

Solution

One semantic layer, four libraries, and a pipeline that can't drift.

The rebuild collapsed the token model, consolidated components into platform libraries, and put Figma and code on one automated rail across Android, iOS and Web.

Foundations

The layer everything else inherits from.

Most of the real work lived here: tokens, type, icons and theming, rebuilt so the right choice is the easy one.

01
Tokens

Three token layers down to one

The legacy model ran L0 primitives (raw hex) → L1 semantic → L2 component-scoped tokens, so designers reasoned about three layers to place one colour. L1v2 is a single semantic layer designers touch, with the system resolving the rest internally.

02
Typography

Messina Sans to Inter

We migrated brand and product to Inter for consistency and availability. Inter's high x-height can read childish at large sizes, so the plan added Inter Display for 20pt and up plus letter-spacing tuning. Naming moved to intent-based names (Heading-1, Body-Default, Meta-Label) so platform values can differ while the intent holds.

03
Craft

Icons, elevation and motion on a grid

Icons moved to the Huge Icons library on a strict 24×24 grid with 1.5px strokes, keeping the same names so nothing downstream broke. Elevation became a seven-level scale on a Y×2=Blur rule with no negative-Y shadows. Motion got easing and duration tokens plus a cross-platform handoff doc, so animation stopped being per-designer improvisation.

04
Theming

Dark mode that resolves itself

Light and dark resolve automatically through alias rebinds, so designers work in one place and both themes stay correct, once we'd fixed the contrast failures the old token pairings were producing.

Exploring the System

We studied the systems we respect, then took a stance.

Benchmark
Material 3
Strengths

A rigorous token architecture and mature theming most teams already recognise.

What we took

A semantic layer designers reason about, instead of exposing raw primitives.

Benchmark
Fluent 2
Strengths

A clear elevation and motion language across a huge surface area.

What we took

A structured elevation scale. Our own study across five systems confirmed none use negative-Y shadows.

Benchmark
Atlassian & Polaris
Strengths

System-as-product thinking: governance, contribution models and deep docs.

What we took

A governance model that scales contribution, plus the leaner “to the point, no BS” docs bar we admired in Wise.

The stance we took

Surface decisions, not variables

Designers don't need 800 tokens. They need to know which one is right here. The system carries the complexity so the designer carries the decision.

Consistency over customization

A shared language beats individual taste. If two designers make the same page look like two products, the system has failed, not the designers.

Govern, don't gatekeep

Rules exist to keep the system lean, not to make the pod a bottleneck. The end state is shared ownership, not a locked door.

Design Decisions

The calls that did the heavy lifting.

Every decision below had to survive the same four facts at once.

Constraints we designed inside

The product could not stop shipping during the rebuild. Engineering demanded traceability, so every change ran through a Jira ticket. Code Connect was fragile, so node-ids couldn't change casually. And the mandate covered three platforms (Android, iOS, Web) that each build tokens differently.

01
Tokens

One semantic layer, L1v2

Decision

Introduce an L1v2 semantic layer and make the old L2 tokens private on release rather than deleting them.

Why

Token overload was the root problem, but a hard delete would break in-flight production designs. Going private, then observing for a month, let us simplify the designer's surface without a big-bang migration.

Rejected

Keeping the full three-layer model exposed. It kept designers debugging tokens instead of designing.

02
Architecture

Separate Mobile and Web systems

Decision

Keep the mobile and web design systems separate, consolidated into four files instead of dozens of per-component libraries.

Why

Platform-specific systems are easier to build and maintain, and Code Connect works cleanly when a web build references web components. Mobile components were being used on web, which had broken that link.

Rejected

A single unified system. Elegant on paper, but it forced compromises neither platform's engineers wanted to maintain.

03
Automation

One-click Figma-to-code sync

Decision

Automate the whole token and icon pipeline instead of syncing by hand.

Why

The manual path meant downloading ~12 files, running a local sync, then raising and merging a PR. It was slow and it drifted. Automating it is the 20+ minutes saved on every update.

Guardrail

A screenshot-regression suite (1000+ tests per run) gates every sync, so automated never means unverified.

04
Patterns

The “3+ Rule” graduation gate

Decision

Split Component from Pattern, and put a usage-based promotion gate between local patterns and the global system.

Why

A pattern graduates to global only once three or more verticals actually use it. That answers “can my thing go in the system?” with evidence instead of politics, and keeps the global library from becoming a dumping ground.

Rollout Challenges

Three tensions we had to design inside.

01
Simplify the model without losing the power

The three-layer token model was genuinely useful. At one point it revealed the exact blast radius of a component change. Collapsing to one semantic layer for designers couldn't mean throwing that away; the complexity had to move inside the system, not disappear. That tension was still a live, healthy debate on the team.

02
Migrate 41 live files without breaking anyone

Engineers referenced 41 production files through Code Connect. Change a node-id and their build breaks. We couldn't freeze the product for a design-system rebuild, so migration had to happen underneath live work, which meant tolerating messy overlap instead of a clean switch.

03
Keep the system lean as everyone wanted in

Once the system worked, every team wanted their pattern in it. Left unchecked, the global library becomes a dumping ground. We needed a way to say “not yet” that felt fair rather than territorial: governance that scaled contribution instead of blocking it.

Impact

One source of truth, measured where we could.

Tokens and icons now match Figma with zero drift, designers trigger syncs without an engineer, and accessibility fixes are merged to main. Adoption and ticket-volume metrics were still being instrumented, so I'm only claiming what was measured.

Reflection

What building Arc taught me.

A design system's job is to remove decisions, not add options

800 tokens felt thorough. It was actually a tax. The system got better the moment we started hiding complexity instead of exposing it. Designers need decisions, not variables.

Governance is as important as components

The “3+ Rule” and the contribution model did more for the system's health than any single component. Without a way to say “not yet”, a good library rots into a dumping ground.

Automation is what makes consistency stick

You can preach “single source of truth” forever, but drift is a manual-process problem. Wiring Figma into the repo is what actually made the promise true and gave designers back 20 minutes an update.

Migrate underneath live work, not instead of it

Tolerating messy overlap (two Code Connect links, a month of private tokens) was uncomfortable but correct. A clean big-bang cutover would have broken 41 files and the team's trust with them.
