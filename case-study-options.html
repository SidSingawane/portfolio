Overview

At Upstox, I worked on designing an Options Strategy Builder — a feature that helps traders build, analyse, and execute multi-leg options strategies within a single workflow.

The goal was to bring decision-making tools closer to execution, reducing the cognitive overhead of options trading for retail users.

Problem

Most retail options traders on Upstox relied on fragmented workflows and external tools to plan strategies. This created friction at every step:

  • Users relied on external tools like Sensibull for strategy analysis
  • Fragmented workflows across multiple platforms broke focus
  • High cognitive load from juggling Greeks, payoff graphs, and pricing
  • Low trust in the platform for decision-making — users trusted Upstox for execution only

Why This Problem Mattered

Options trading in India was exploding. Weekly expiry options had turned retail traders into active participants. But the tools hadn't kept up. The goal was to unify the entire build → analyse → execute flow into one cohesive experience that earned users' trust.

Industry Context

Understanding the landscape that shaped the design decisions.

The Rise of Retail Options Trading

India's options market had grown exponentially, driven by weekly expiry contracts and mobile-first trading behavior. Retail traders — many of them new to derivatives — were executing complex multi-leg strategies with tools that weren't designed for them.

The Complexity Challenge

Options trading is inherently complex. Every decision involves reading Greeks, understanding implied volatility, assessing risk-reward across multiple legs, and timing execution precisely. Most platforms either dumbed this down too much or presented everything at once — neither approach served the user well.

"Users trusted Upstox for execution, but not for decision-making."

Design Challenges

Navigating the tension between analytical depth and interface clarity.

01
Complexity vs Clarity

Options strategies involve multiple variables changing in real-time. The challenge was presenting enough information for informed decisions without overwhelming users. We used progressive disclosure to layer information based on user expertise and task context.

02
Mobile Constraints

Most Upstox traders are mobile-first. Building a multi-leg strategy on a small screen required rethinking information hierarchy. We prioritized the payoff graph and key metrics, using expandable panels for deeper data like individual Greeks per leg.

03
Real-Time Performance

Options prices change every second. The interface needed to update Greeks, payoff graphs, and margin requirements in real-time without creating visual noise or cognitive overload. We used subtle animation and color-coded deltas to communicate changes smoothly.

Design Solutions

Key design decisions that shaped the final experience.

01
Feature

Dedicated Strategy Builder

A full-screen, focused workspace where traders construct strategies leg by leg. The interface adapts its information density based on the number of legs added, progressively revealing complexity.

02
Feature

Persistent Payoff Graph

The payoff visualization stays anchored while users modify legs. Real-time updates show how each change affects the overall risk-reward profile, giving immediate visual feedback for every decision.

03
Feature

Dual Entry System

Users can build strategies either from scratch (custom legs) or from templates (pre-built strategies like Iron Condor, Bull Call Spread). Both paths converge into the same builder, so users always end up in a familiar workspace.

04
Feature

Progressive Disclosure

Greeks, margin requirements, and detailed breakeven analysis are available but not front-loaded. Users access deeper data through expandable panels, keeping the primary view clean and decision-focused.

05
Feature

Save & Reuse Strategies

Traders can save their strategies for weekly reuse. Saved strategies auto-populate with current market data when reopened, reducing setup time for recurring trades.

06
Feature

Execution Layer

A streamlined order review screen that summarizes all legs, total margin required, and net premium. One-tap execution with clear confirmation states and fallback handling for partial fills.

Design Iterations

How the design evolved through rapid prototyping, testing, and stakeholder feedback.

V1
Problem

Initial concept tried to show everything at once — Greeks, graph, legs, and order form on a single screen.

Improvement

Split into distinct zones with progressive disclosure. Reduced visual density by 40%.

V2
Problem

Template selection felt disconnected from the builder. Users lost context switching between views.

Improvement

Merged template picker into the builder as an inline overlay, maintaining spatial continuity.

V3
Problem

Payoff graph was too small and lacked interactivity. Users couldn't explore scenarios.

Improvement

Made graph expandable to full-width. Added touch/hover to explore P&L at any price point.

V4
Problem

Mobile leg editing required too many taps. Adding strike + type + qty felt tedious.

Improvement

Introduced quick-edit swipe gestures and smart defaults based on the previous leg configuration.

V5
Problem

Execution confirmation lacked clarity on total risk. Users hesitated at the final step.

Improvement

Added a visual summary card showing max loss, max profit, and breakeven. Reduced last-step hesitation by 28%.

Key Learnings

Principles that emerged from this project and now shape how I approach financial product design.

Financial UX is Decision Design

In fintech, the interface isn't just a tool — it's a decision environment. Every element either reduces or adds cognitive load. Design for clarity of consequence, not just usability.

Progressive Disclosure is Critical

Showing everything at once kills confidence. Layering information based on user intent and expertise creates a sense of control — which is what traders actually need.

Systems Thinking Scales Better Than Screens

Designing individual screens is easy. Designing a system where every module works together — payoff graph, Greeks, legs, execution — is what makes the experience feel cohesive.

Behavior Beats Assumptions

We assumed advanced traders wanted maximum data density. Research showed they wanted speed and confidence, not more numbers. Always validate — even with expert users.

Reflection

This project reinforced that designing for financial products is really designing trust systems. Every interaction either builds or erodes a trader's confidence in their own decisions.

The best financial UX doesn't just present data — it creates a behavioral system where power, clarity, emotion, and risk all exist in balance. The strategy builder became that system.

It was a reminder that the real design challenge in fintech isn't making things simpler. It's making complexity feel navigable.
